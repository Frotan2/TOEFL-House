# TOEFL House — Academic System

**STATUS: CURRENT CANONICAL — NORMATIVE**

## Academic model

The governed academic hierarchy is:

`Academic Period/Calendar → Program → Program Version → Level → Offering → Class`

## Delivery lifecycle

`Offering → Class → Capacity → Enrollment → Attendance/Assessment → Progression → Graduation → Transcript`

## Supporting authorities

- Placement owns assessment evidence and recommendation.
- Scheduling owns timetable/room/assignment constraints within approved boundaries.
- Enrollment controls enrollment state and waitlist semantics.
- Academic controls academic lifecycle decisions.
- Payment gating is enforced by canonical financial/application boundaries, not by UI-only state.

## Capacity

Capacity is an invariant, not a display value. Database constraints guard critical relationships, including the offering/class capacity relationship where applicable.

## Evidence

Placement, assessment, progression and graduation must retain the evidence needed to explain why a decision occurred.

## Target-state gaps

Remaining gaps are breadth/operational maturity, not a second academic authority. Examples include selected scheduling/enrollment boundary refinements and richer portal/reporting experiences.
